# Kopi v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sincronizar el portapapeles (texto + imágenes) entre un Android y una Mac en ambas direcciones, automáticamente, por Wi-Fi local.

**Architecture:** La Mac es el servidor: WebSocket sobre TLS 1.3 mutuo, anunciado por Bonjour como `_kopi._tcp`. Android es el cliente: lo descubre con NSD y mantiene la conexión desde un servicio en primer plano. La lógica pura (modelos del protocolo, `SyncEngine`, `Preview`) existe en Swift y en Kotlin. Las dos versiones se mantienen alineadas con los mismos fixtures JSON de `protocol/fixtures/` y los mismos casos de prueba.

**Tech Stack:**
- **Mac:** Swift 6 (SwiftPM, Command Line Tools), SwiftUI `MenuBarExtra`, Network.framework, CryptoKit, swift-certificates, Keychain, `SMAppService`.
- **Android:** Kotlin, corrutinas, Jetpack Compose, Shizuku API, `NsdManager`, OkHttp, Android Keystore, CameraX + ML Kit (bundled), kotlinx.serialization, DataStore.
- **Repo:** Makefile y GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-25-kopi-design.md`

## Global Constraints

- Identificador de app (Mac y Android): `dev.alorebb.kopi`. Nombre visible: `Kopi`.
- Servicio Bonjour: `_kopi._tcp`. Puerto fijo del servidor Mac: `47474`.
- `protocolVersion` = `1`. Versión de app inicial: `1.0.0`.
- Android: `minSdk 31`, `targetSdk 35`, `compileSdk 35`. Mac: macOS 14+ (`.macOS(.v14)`).
- Caducidad de ofertas y de reenvío al reconectar: `120_000` ms. Código de vinculación: 128 bits, caduca a los `300_000` ms y sirve una sola vez.
- Imágenes: solo `image/png` o `image/jpeg`. Máximo `20 * 1024 * 1024` bytes. Fragmentos de `256 * 1024` bytes. Espera al pegar en la Mac: `5` s.
- Texto: máximo `4 * 1024 * 1024` bytes en UTF-8 (decisión del plan; ver Review Focus 2).
- Huella: SHA-256 del certificado DER, en hexadecimal minúsculo de 64 caracteres. Claves P-256.
- Reconexión: espera creciente 1, 2, 4, 8, 16, 30, 30… segundos. *Ping* de WebSocket cada `30` s.
- Vista previa: máximo `40` caracteres seguidos de `…`; `tarjeta •••• NNNN`; `contenido oculto`; `imagen`.
- **Los logs nunca contienen contenido del portapapeles.** Solo `kind`, `size` e `id`.
- **Ningún secreto en el repo.** Las claves solo viven en el Keychain y en el Android Keystore.
- Todo texto visible sigue la tabla de copy de la spec §8 al pie de la letra y la guía *ux-heuristics*: qué pasó, cómo se arregla, botones verbo + sustantivo.
- Commits con el trailer de la sesión (`Co-Authored-By` + `Claude-Session`).

## Review Focus

1. **Mac despierta tras dormir:** el listener y el anuncio de Bonjour pueden quedar inservibles. El teléfono debe reconectar en segundos. → Test `restartAcceptsNewConnection` en la Task 9, y observar `NSWorkspace.didWakeNotification` en la Task 11.
2. **Texto enorme** (por ejemplo, un log de 10 MB): OkHttp rechaza mensajes de más de 16 MiB. No debe colgarse ni desconectarse; se omite el envío. → Test `oversizedTextIsNotSent` en las Tasks 4 y 6.
3. **Portapapeles vacío o solo espacios** (algunas apps lo limpian): no debe borrar el portapapeles del otro equipo. → Test `emptyOrWhitespaceIsNotSent` en las Tasks 4 y 6.
4. **Volver a copiar lo mismo tras recibirlo:** si el teléfono recibió A, la Mac copió B y luego el teléfono vuelve a copiar A, A **debe** enviarse. La supresión de eco solo aplica al último contenido escrito desde el remoto. → Test `recopyAfterOtherRemoteIsSent` en las Tasks 4 y 6.
5. **Ráfaga de copias** (tres copias en 1 s): el destino debe quedar con la última, aunque los mensajes lleguen fuera de orden. → Test `olderRemoteIsIgnored` en las Tasks 4 y 6.

### Task 4: SyncEngine (Mac)

**Files:**
- Create: `Sources/KopiCore/SyncEngine.swift`, `Tests/KopiCoreTests/SyncEngineTests.swift`

**Interfaces:**
- Consumes: `KopiMessage`, `Limits` (Task 2).
- Produces:

```swift
public enum LocalContent: Equatable { case text(String, sensitive: Bool), image(mime: String, size: Int, sha256: Data) }
public enum ImageStrategy { case lazy, eager }       // Mac = .lazy, Android = .eager
public enum EngineAction: Equatable {
    case send(KopiMessage)
    case writeText(String, id: UUID)
    case registerImagePromise(id: UUID, mime: String, size: Int)   // solo .lazy
    case requestImage(id: UUID)                                    // .eager al recibir oferta; .lazy al pegar
}
public enum ImageServe: Equatable { case serve(id: UUID), unavailable(UnavailableReason) }
public final class SyncEngine {
    public init(strategy: ImageStrategy, now: @escaping () -> Int64, newID: @escaping () -> UUID = UUID.init)
    public func onLocalCopy(_ c: LocalContent) -> KopiMessage?        // nil = no enviar
    public func onRemote(_ m: KopiMessage) -> [EngineAction]
    public func didApplyRemote(_ c: LocalContent)                    // llamar tras escribir en el portapapeles local
    public func onImageRequest(id: UUID) -> ImageServe
    public func onReconnect() -> KopiMessage?
    public var lastItem: (preview: PreviewInput, ts: Int64)? { get }
}
```

**Reglas** (spec §6.4 y Review Focus):
- La supresión de eco compara con la **última** `LocalContent` aplicada desde el remoto. Las imágenes se comparan por `sha256`.
- Se rechaza el remoto si su `ts` es menor que el `ts` local vigente. Si los `ts` empatan, gana el `id.uuidString` mayor.

- [ ] **Step 1: Escribir los tests que fallan.** Usa un reloj falso, `var t: Int64 = 1_000_000`, y estos nombres y aserciones:
  - `localTextIsSent`: `onLocalCopy(.text("hola", false))` devuelve `.clip` con `text == "hola"`, `ts == t` y `sensitive == false`.
  - `emptyOrWhitespaceIsNotSent`: devuelve `nil` con `""` y con `"  \n"`.
  - `oversizedTextIsNotSent`: devuelve `nil` con un texto de `4*1024*1024 + 1` bytes.
  - `echoIsSuppressed`: `didApplyRemote(.text("A"))` y luego `onLocalCopy(.text("A"))` da `nil`.
  - `recopyAfterOtherRemoteIsSent`: aplica remoto A, aplica remoto B, y entonces `onLocalCopy(A)` no es `nil`.
  - `remoteTextIsWritten`: `onRemote(.clip(text "X"))` devuelve `[.writeText("X", id)]`.
  - `olderRemoteIsIgnored`: tras una copia local en `t`, `onRemote(clip con ts t-1)` devuelve `[]`.
  - `lazyOfferRegistersPromise`: con `.lazy`, `onRemote(.clipOffer)` devuelve `[.registerImagePromise(...)]`.
  - `eagerOfferRequestsImmediately`: con `.eager`, devuelve `[.requestImage(id)]`.
  - `oversizedImageIsNotOffered`: con `size = 20MB + 1`, devuelve `nil`.
  - `imageRequestServesCurrent`: `onImageRequest` con el id de la oferta vigente devuelve `.serve`.
  - `imageRequestExpired`: tras `t += 120_000`, devuelve `.unavailable(.expired)`.
  - `imageRequestReplaced`: si ya hubo otra copia local, el id viejo devuelve `.unavailable(.replaced)`.
  - `reconnectResendsRecent`: con `t += 119_999`, devuelve el último mensaje; con `t += 120_000`, devuelve `nil`.
  - `reconnectNeverResendsRemoteOrigin`: si lo último vino del remoto, devuelve `nil`.
- [ ] **Step 2: Ejecutar** `swift test --filter SyncEngineTests`. Resultado esperado: FAIL.
- [ ] **Step 3: Implementar `SyncEngine`.** Es una clase síncrona, no thread-safe; el coordinador la llama desde un solo actor o cola.
- [ ] **Step 4: Ejecutar** `make mac-test`. Resultado esperado: PASS.
- [ ] **Step 5: Commit.** `feat(mac): sync engine rules (echo, conflicts, expiry, reconnect)`
